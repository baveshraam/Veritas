8.Data Foundation

Summary of the 19-dimension synthetic-data audit in docs/DATA_GENERATION_AUDIT.md, updated with what North Star Phase 2 subsequently fixed.

Solid — verified directly in code, not merely asserted

  • Schema conformity — the organizers' 27-table ER reproduced verbatim, enforced by a failing test if anyone alters it.
  • Referential integrity — every foreign/business key resolves; the one dimension the test suite over-invests in relative to its risk.
  • Recurring identities & identity ambiguity — the strongest-engineered part of the generator; the two real, non-obvious statistical bugs found and fixed here (EM contamination in the Fellegi-Sunter u-estimate, string-concatenation inflation in the name comparator) are documented with the reasoning that led to them.
  • Co-offending structure — crew-weighted preferential attachment, the property that makes Louvain find 12 realistically-sized communities instead of one blob holding 254 of 255 people.
  • Financial ground truth — kept genuinely separate from detector output: injected laundering patterns are written to a file, never to the column the detectors read.
  • Graph structural integrity — best-tested dimension in the generator.
  • Reproducibility — full generation determinism, seeded per case.
  • Leakage rules — both the AML-label separation and the no-protected-attribute-as-feature rule are genuinely enforced in code, independently re-verified this pass.

Fixed this pass

  • Narrative diversity (BUG-023) — was the audit's own top-priority finding: 12 of 20 crime types produced zero descriptive narrative content; the other 8 produced exactly one fixed sentence each. This degraded two real user-facing features (FIR semantic search and the Copilot's "similar past cases"). Now all 20 crime types carry 3 MO variants plus per-case slot-filling, backfilled live without touching any other row.
  • No narrative-diversity test existed — the reason BUG-023 survived to manual discovery instead of CI. A regression test was added alongside the fix.

Cosmetically imperfect but fine as-is (per the audit's own verdict, unchanged)

  • Priors CSVs are self-described as "approximate pending ETL," not fully-sourced NCRB figures — already honestly disclosed in code.
  • Geographic attractors are synthetic stand-ins for real POI data — algorithmically real clustering, substantively synthetic placement, already disclosed in geo.py's own docstring.
  • Case status has no age-coupling; its realized distribution isn't tested against input rates — low risk, nothing currently reads this joint relationship.
  • AML injected patterns are the only "dirty" examples in the dataset — detector specificity against organic-but-innocent transaction bursts is untested. Worth knowing if a judge asks about false-positive risk.
  • No seasonal signal in generated incident timing — Prophet's seasonality terms fit noise on this dataset. Avoid leaning on "the forecast captures a weekly pattern" in a demo.

Remaining gap — not yet addressed

  • Identity answer key not persisted post-generation. The claimed F1 0.989 (independently corroborated at 0.998 on a 600-case sample) can currently only be recomputed against a fresh in-process generate() call, not against whatever dataset is actually live on Catalyst — unlike the AML labels, which already follow the correct persist-as-artifact pattern.
Summary verdict, from the audit itself: "Mostly yes, with one clearly broken capability [now fixed] and a handful of honestly-disclosed but under-tested approximations." The generator's hardest problems — identity, co-offending, AML ground-truth separation, determinism — are solved to the "best solution, not fastest" standard the project sets for itself.
